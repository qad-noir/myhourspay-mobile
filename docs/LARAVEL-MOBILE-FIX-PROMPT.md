# Laravel prompt: mobile editing and web device sessions

Continue the existing Laravel MyHoursPay native mobile API. Read docs/api/mobile.openapi.yaml, docs/api/mobile-integration.md and applicable AGENTS.md first.

The Flutter app already calls PATCH /api/v1/mobile/workspaces/{workspace}/hours/{entry} with the documented version and Idempotency-Key. Do not add a duplicate route. Investigate why a valid owned entry returns 404 on production MySQL while local SQLite editing works.

In app/Http/Controllers/Api/MobileWorkspaceController.php::saveHours, the guard currently uses strict comparisons of entry.workspace_id and entry.user_id against model IDs. Production GET hours responses have shown decimal-string foreign keys. Normalize IDs safely through integer model casts or equivalent comparisons before authorization, maintaining user/workspace isolation. Check equivalent strict ownership guards in MobileTimesheetController and serializers. Return contract-compatible numeric IDs, preserving nullable IDs. Verify authorized editing, cross-user/cross-workspace rejection, missing entries, version conflicts, locked timesheets and idempotency replay; include a regression that actually exercises string-backed foreign keys, plus MySQL integration evidence where available. Do not disable ownership checks or treat all 404s as deployment failures.

Add a Mobile devices section to /user/profile alongside the existing Jetstream browser sessions section (resources/views/profile/show.blade.php and profile/logout-other-browser-sessions-form.blade.php). The existing browser sessions component only reads browser sessions; native login creates Sanctum tokens whose names start mobile:. Show only the signed-in user's nonexpired mobile tokens: device display name without mobile: prefix, last activity and expiry. Distinguish unused from expired sessions. Never expose token values, hashes or tokens in URLs. Add a password-confirmed, CSRF-protected action to revoke an individual owned mobile token with clear success/error feedback and cancelable confirmation. Preserve browser-session controls and the mobile API's mobile-only session listing. Test owner isolation, filtering, cancellation, revocation and rejection of foreign token IDs. A revoked token must fail the next mobile API request with 401. Avoid inventing refresh endpoints.

Also return a friendly work_date duplicate validation message: "This date already has an entry. Try editing it instead." Preserve the documented validation envelope and status 422.

Work locally/staging by default; use designated test-login/test-login.txt credentials without logging them. Make incremental commits with meaningful tests. Report deployment steps and actual integration evidence. Do not claim production is fixed until the patch is deployed and an authorized real mobile edit succeeds.
